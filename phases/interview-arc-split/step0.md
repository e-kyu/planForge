## 작업

목표: `interview.md`(327줄)를 **공통 base + 문서 타입별 아크 조각**으로 분리하고, 로더가 세션 `doc_slug`에 따라

핵심 설계 의도:
- 아크 조각은 **절대 공통 규칙을 복제하지 않는다** — 아크 서사·예시 질문·[문서] 체크리스트 항목·plan 구성

- 조각은 **자체 섹션 헤딩으로 자기완결**한다 (로더가 헤딩을 만들지 않는다).
- 기존 콘텐츠 이동 시 **문구를 축약·순화하지 않는다** — 기존 테스트 단언(`"제안서 구성 가이드"`,

  취득되어야 녹색이 유지된다. 이동이 곧 원문 보존의 증명이다.

```markdown

### 아크 서사와 주제 그룹 (예시 질문 포함)

- **UI·UX설계서 아크**: 대상 사용자·페르소나 → 화면 목록·정보 구조 → 사용자 흐름 →
  UI 디자인 방향 → 접근성·제약·비목표 (아래 주제 그룹 5개). 각 주제는 결정 + 이유 + 근거
  (소스·팩트 — 대화 로그 항목 또는 `(미확정)`)를 함께 수집해 주제당 1개 팩트로 적립한다.
  정해지지 않은 항목은 `(미확정)` 팩트로 적립하고 "언제까지·어떻게 확정할지"까지 묻는다.
  라운드당 최대 4문항이므로 주제 그룹 5개는 최소 2라운드에 나눠 묻는다. 예시 질문
  (옵션 카드 = 라벨 — 설명):
  - 대상 사용자·페르소나 → "이 화면들을 주로 누가 쓰게 되는지 사용자 유형을 정하고
    싶습니다. 주요 사용자와 각자의 목표를 알려 주시겠어요?"
    (실무 담당자 — 등록·조회 같은 반복 업무를 매일 수행) / (관리자 — 승인·설정을 주기적으로
    수행). 사용자 유형별 니즈·목표는 서술형으로 수집한다.
  - 화면 목록·정보 구조 → "산출할 화면 목록과 메뉴·화면 구조를 정하고 싶습니다. 어떤
    화면들이 필요하고, 화면은 어떻게 묶을까요?" 화면 목록(화면명·목적·주요 요소)은
    서술형(allow_free)으로 수집하고, 메뉴·계층 구조는 결정표+이유로 확정한다.
  - 사용자 흐름 → "핵심 업무 시나리오가 화면 사이에서 어떻게 흐르는지 정하고 싶습니다.
    대표 흐름의 단계와 화면 전환을 알려 주시겠어요?"
    (정상 흐름 확정 — 성공 경로의 단계·화면 전환을 먼저 고정) / (예외·분기 포함 —
    실패·되돌리기 경로까지 확정). 흐름 단계는 근거(소스·팩트)와 함께 주제당 1개 팩트로
    적립한다.
  - UI 디자인 방향 → "화면의 톤과 밀도·레이아웃 방향을 어떻게 잡을까요?"
    (밀도 우선 — 정보를 한 화면에 배치, 데이터 많은 업무 화면) / (단순성 우선 — 단계
    분할·여백, 현업 온보딩 부담이 큰 화면). 기존 화면·디자인 시스템 재사용 여부도 함께
    확인한다.
  - 접근성·제약·비목표 → "지켜야 할 접근성·기술 제약과 이번에 하지 않을 것을 정하고
    싶습니다." 서술형으로 "제약 + 적용 범위 + 이유"와 하지 않는 것(비목표)을 명시로
    수집한다 — 화면 확장·리디자인 범위를 고정해 임의 확장을 막는 목적이다.

### [UI·UX설계서] 체크리스트 항목

- [UI·UX설계서] 대상 사용자·페르소나 확정 — 사용자 유형별 니즈·목표를 근거와 함께 정리
- [UI·UX설계서] 화면 목록 확정 — 산출 화면과 각 화면의 목적을 근거와 함께 정리
- [UI·UX설계서] 정보 구조(메뉴·화면 계층) 확정 — `[유형: 구성]` 슬라이드로 확보
- [UI·UX설계서] 주요 사용자 흐름 확정 — 대표 시나리오의 단계·화면 전환을 근거와 함께
- [UI·UX설계서] UI 디자인 방향 확정 — 톤·밀도·레이아웃 원칙의 결정+이유 포함
- [UI·UX설계서] 접근성·제약·비목표(하지 않는 것) 기재 — 미확정은 `(미확정)` 표기

### UI·UX설계서 plan 구성 가이드 (사용자·화면 슬라이드)

- 사용자·페르소나: `[유형: 표]` — 헤더 예시 `- 표: [사용자 유형 | 특징 | 니즈]`,
  행은 확정 팩트에서만 채우고 결정되지 않은 항목은 니즈 칸에 `(미확정)`을 적는다
- 화면 목록: `[유형: 표]` — 헤더 예시 `- 표: [화면 | 목적 | 주요 요소]`
- 정보 구조: `[유형: 구성]` — `- 구성:` 아래 `메뉴·계층명 | 화면 라벨, 화면 라벨, ...`
  한 줄 = 계층 1개 (계층 최대 6개·계층당 박스 최대 6개, 라벨 안에 쉼표 금지 — 서버가
  검증한다). 계층은 상→하(메뉴 → 화면 그룹 → 화면) 권장
- 사용자 흐름: `[유형: 표]` — 헤더 예시 `- 표: [단계 | 화면 | 행동]`. 예외·분기가
  두드러지는 흐름은 `[유형: 2단]` — `- 좌 (정상 흐름):` / `- 우 (예외·분기):` 아래
  `라벨 | 설명` 한 줄씩
- UI 디자인 방향·제약·비목표: `[유형: 표]` — 헤더 예시
  `- 표: [항목 | 방향 | 이유 | 상태]` (결정표 — 결정되지 않은 항목은 상태 칸에
  `(미확정)`을 적는다)
- 와이어프레임·스토리보드 같은 별도 슬라이드 유형은 없다 — 화면 목록·흐름·구조는 모두
  위 7종 규약(표지/목차/2단/표/차트/구성/마무리)의 표·구성·2단으로 표현한다
- 마무리: 남은 `(미확정)`의 확인 계획("언제까지·어떻게")과 다음 단계 요청 문장
  (와이어프레임·프로토타입 제작 등)을 `- 핵심문장:`에 실는다
- 목차 불릿은 아크 순서의 장 라벨을 쓴다 (예: `- 핵심문장: 01 사용자와 화면 구조 /
  02 사용자 흐름 / 03 UI 디자인 방향 및 요청 사항`)
- 문서 태그 규칙은 아래 plan.md 포맷 섹션의 '문서 태그 규칙'을 따른다 (단일 문서
  프로젝트는 태그 없음)
```

### 4. 로더 `agent.py`

현재 `_system_prompt()`(:110-131)는 interview.md 전문을 읽어 주입 컨텍스트·리마인더를 접미 조립한다.
조립은 유지하고, base 중간의 `<!--ARC-->` 마커를 아크 조각으로 치환하도록 확장한다:

```python
ARC_MARKER = "<!--ARC-->"       # interview.md 내 아크 조각 치환 지점 (계약 — docs/INTERVIEW-TURN-CONTRACT.md에 기록)
ARC_LEGACY_SLUG = "proposal"    # 레거시 세션(doc_slug=None) 폴백 — "레거시는 제안서 아크로 진행" 계약 준수

def _arc_section(self) -> str:
    slug = self.sess.doc_slug or ARC_LEGACY_SLUG
    return (PROMPTS_DIR / f"arc_{slug}.md").read_text(encoding="utf-8-sig").rstrip("\n")

def _system_prompt(self) -> str:
    base = (PROMPTS_DIR / "interview.md").read_text(encoding="utf-8-sig")
    if ARC_MARKER not in base:
        raise RuntimeError(f"interview.md에 아크 마커({ARC_MARKER!r})가 없다 — 로더 계약 위반")
    prompt = base.replace(ARC_MARKER, self._arc_section())
    ctx = self._turn_context()
    return (prompt + "\n\n## 이번 턴 주입 컨텍스트 (...)\n\n" + ctx
            + "\n\n## 이번 턴 ask_questions 리마인더 (...)\n\n" + self._remind_ask())
```

- 최종 시스템 프롬프트 순서: `# 인터뷰 에이전트`(base) → `## 이번 인터뷰 아크: …`(조각) →
  `## plan.md 포맷` → `## ask_questions 인자 형식` → `## 톤`(base) → 주입 컨텍스트 → 리마인더.
- `## 이번 턴 주입 컨텍스트` 헤더·`_remind_ask()` 위치는 **무변경** — 리마인더가 프롬프트 맨 끝이어야 한다는
  기존 계약 유지 (`test_system_prompt_carries_fewshot_and_reminder` 잠금).
- 읽기 인코딩은 기존과 동일 `utf-8-sig` (base·조각 공통). 미상 slug는 `FileNotFoundError`로 조기 실패 —
  OK (세션 생성 시점에 `docloops.require_session_doc()`이 DOC_KINDS로 통제).

- `backend/app/agents/tools.py`의 스키마·검증(`_validate_update_checklist` 포함)을 수정하지 마라. 이유:
