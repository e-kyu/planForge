- `/CLAUDE.md` — 엔진 패키지 구조(`packages/planforge-cli/`), "빌더는 legacy 바이트 동일 이식본 —

- `/phases/refine-tone-strings/step0.md`~`step2.md` — 이전 step(완료). 기준표는 step1.md의 용어 순화 기준표.

## 작업

목표: 엔진 패키지(`packages/planforge-cli`)가 출력하는 문자 — 검수 발견사항(ReviewPanel에 그대로
표시됨), 오류 메시지(422/job.error로 노출), CLI 출력 — 을 자연스러운 친절한 한국어로 순화한다.

기준표는 `phases/refine-tone-strings/step1.md`의 **용어 순화 기준표**를 따른다. 추가로:

| 해소 / 해소하세요 | 해결 / (미확정)을 확정 수치로 바꾸세요 |

### 반드시 함께 갱신할 테스트

수정하는 문자를 assert하는 테스트(예: numcheck 발견사항 형식, filter/parser 오류 메시지, derive
재시도 메시지를 잠그는 `tests/` 하위 테스트)를 grep으로 찾아 같은 step에서 갱신한다. 테스트가
잠그는 것은 **메시지의 구분적 substring**(예: "슬라이드", 수치 포맷)일 수 있으므로, 잠금 substring이
보존되면 테스트 수정이 불필요하다 — 실패하는 테스트만 최소한으로 갱신한다.

## 금지사항

- `builders/build_ppt.py`·`builders/build_doc.py`·`theme.py`를 수정하지 마라. 이유: legacy 바이트
  동일 이식본이라 로직 변경이 금지되어 있고("제목없음" 폴백 포함), 토큰 4종 세트 계약이 붙어 있다.
- 파서 키워드(`표:`, `구성:` 등)·`(미확정)` 마커·슬라이드 유형 라벨을 바꾸지 마라. 이유: 프롬프트와
  파서가 이 키워드로 계약되어 있어 바꾸면 plan 해석이 깨진다.
- `llm/prompts/derive_slides.md`·`derive_report.md` 프롬프트를 수정하지 마라. 이유: 내부에 파서가
  해석하는 계약어가 포함되어 있어 프롬프트-파서 동기화가 필요한 별도 작업이다. 이 step은 코드 출력만.
- numcheck의 exit code 계약(위반 시 exit 1)을 바꾸지 마라. 이유: CLI 소비자가 종료 코드로 판정한다.
- 로그의 grep 키워드(예: "[tool-loop]")를 바꾸지 마라. 이유: 진단 스크립트가 키워드로 필터링한다.
- 기존 테스트를 깨뜨리지 마라 — 잠금 substring 보존 우선, 실패 테스트만 최소 갱신.
