# /numcheck — 수치 무결성 대조 검증

설계 원칙 계약 3번(수치 무결성) 검증: plan 원본과 파생물 간에 수치·표·차트 데이터·
`(미확정)` 표기·근거/출처 문자열이 한 글자도 다르지 않은지 대조한다.
재구성(개조식→서술형)은 문장에만 허용되며 수치에는 적용되지 않는다.

## 절차

1. 자동 검사가 존재하는지 확인한다:
   - M1 이후: `backend/tests/`의 수치 무결성 단위 테스트를 실행한다(상시 실행 대상).
   - 자동 검사 미확보 시: 아래 수동 절차로 수행한다.
2. **수동 절차** (자동 검사 미확보 시):
   - 대상: plan 원본(SSOT — DB `Plan` 레코드 또는 plan.md)과 파생물(slides.json, report.json, 산출물).
   - plan에서 수치·표 데이터·차트 데이터·`(미확정)`·근거/출처 문자열을 모두 추출한다.
   - 파생물에서 같은 항목을 추출해 **문자열 정확 일치**로 대조한다.
     (수치 포맷 변경, 단위 재표기, 반올림도 위반 — 재구성은 문장에만 적용.)
   - 불일치 목록을 파일·필드 단위로 보고하고, 원본 쪽 값이 무엇이었는지 명시한다.
3. 불일치 발견 시 파생물을 직접 수정하지 않는다 — plan을 확인한 뒤 파생 단계를
   다시 실행하는 경로로만 수정한다(SSOT 계약).

## 대상 경로 주의

`workspaces/*/work/*.json`, `workspaces/*/output/*`는 읽기만 가능(쓰기는 가드 훅이 차단).
테스트 fixture는 `tests/fixtures/`를 사용한다.
