# /compact-log — interview-log.md 압축

$ARGUMENTS

`docs/interview-log.md`가 비대해졌을 때 팩트 손실 없이 압축한다. 압축은 통합 + 아카이브 방식으로 한다.

## 절차

0. **프로젝트 결정**: `$ARGUMENTS`를 프로젝트명으로 해석해 `<P>` = `projects/<프로젝트명>/`로 확정한다. 인자가 없으면 `projects/*/plan.md`를 나열해 사용자에게 선택받는다(1개여도 확인). 규칙 상세는 `CLAUDE.md`의 "프로젝트 결정 규칙" 참조.
1. **현황 파악**: `<P>/docs/interview-log.md`를 읽어 항목 수·중복 후보·대체된 항목(같은 주제의 이전 값)을 정리해 사용자에게 보여주고 압축 범위를 승인받는다.
2. **아카이브 분리**: 통합으로 흡수되는 이전 값·이미 plan.md에 반영 완료된 오래된 세션 항목을 `<P>/docs/interview-log-archive.md`로 이동한다.
   - 파일이 없으면 원본과 동일한 헤더 구조로 생성하고, 상단에 "압축 시 밀어낸 이전 팩트 이력. 참고용으로만 읽는다"를 명시한다.
   - 이동 항목은 원문 그대로 보존 + `[archive: YYYY-MM-DD]` 이동 표기를 붙인다.
3. **원본 통합**: 남은 활성 팩트를 주제별로 통합한다 — 같은 항목이 여러 번 기록된 경우 최종 확정값 하나만 남기고 `(초기 안: N, archive 참조)` 괄호 표기를 붙인다. 날짜·출처 표기 형식(`[YYYY-MM-DD] 항목: 내용 (출처: ...)`)은 유지한다.
4. **참조 무결성 점검**: `<P>/plan.md`의 `interview-log [YYYY-MM-DD] 항목` 인용이 압축 후에도 해석되는지 확인한다. 항목 라벨은 원칙적으로 유지하고, 통합으로 라벨을 바꿨다면 plan.md의 근거/출처 표기를 함께 수정한다. 점검 범위는 같은 프로젝트 내부로 한정한다 — 다른 프로젝트의 plan.md·로그와 교차하지 않는다.
5. **보고**: 압축 전/후 줄 수, archive 이동 항목 수, 미확정 항목 현황을 보고한다.

## 주의

- **팩트 손실 금지**: 모든 확정 팩트는 활성 파일 또는 archive 어디엔가 존재해야 한다. 판단이 서지 않으면 남긴다.
- **미확정 / 확인 필요 섹션은 절대 삭제하지 않는다** — 활성 파일에 그대로 유지한다.
- 수치·내용은 한 글자도 바꾸지 않는다 (통합·이동만 한다). 문구 다듬기는 하지 않는다.
- archive는 쓰기 전용 이력이다 — review-doc 대조는 활성 파일 기준을 유지하므로, 최신 확정값이 반드시 활성 파일에 남는다.
- 압축 전 내용은 archive 파일이 유일한 보존 지점이다 (프로젝트 문서는 git 미추적 정책이므로 이력으로 복구할 수 없다) — archive 파일이 1차 참조점이다.
