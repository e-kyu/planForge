# /review-doc — plan.md · 파생물 · 산출물 전체 검수

$ARGUMENTS

생성된 산출물(PPT·md·html·docx)을 검수하고 문제를 원본(plan.md)에 반영한다.

## 절차

0. **프로젝트 결정**: `$ARGUMENTS`를 프로젝트명으로 해석해 `<P>` = `projects/<프로젝트명>/`로 확정한다. 인자가 없으면 `projects/*/plan.md`를 나열해 사용자에게 선택받는다(1개여도 확인). 규칙 상세는 `CLAUDE.md`의 "프로젝트 결정 규칙" 참조.
1. **대상 확인**: `<P>/output/`의 각 확장자별 최신 산출물(pptx·md·html·docx)과 대응하는 `<P>/work/slides.json`·`<P>/work/report.json`, 그리고 `<P>/plan.md`를 읽는다. 존재하는 파생물만 검수한다.
2. **구조 검수** (파생물 ↔ plan.md 대조):
   - 슬라이드·섹션 수·순서·유형 일치 여부
   - 유형별 필수 요소 누락 (표: 헤더/행, 차트: 데이터/축, 구성: 계층/구성요소, 표지: 제목/날짜)
   - 유형 표기가 7종(표지/목차/2단/표/차트/구성/마무리) 안에 있는지
3. **문서 태그 검수** (plan.md에 `산출 문서`가 2개 이상일 때):
   - 모든 슬라이드 태그가 메타 `- 산출 문서:` 어휘의 부집합인지
   - 선언된 각 문서가 표지·목차·마무리·내용 슬라이드를 최소 1개씩 갖는지
   - 각 문서의 목차 불릿이 실제 태그 필터 결과와 일치하는지 (누락·과다 참조 없는지, 01..NN 재채번 정합)
4. **수치 무결성 검수** (report.json ↔ plan.md 대조 — 문서체 재구성 검증):
   - 수치·표·차트 데이터·`(미확정)` 표기가 plan.md와 **한 글자도 같은지** 대조 (숫자를 추출해 대조)
   - 문장체 재구성으로 주장의 **강도·범위가 왜곡**되지 않았는지 (개조식→서술형 변환 시 과장/축소)
   - plan에 없는 내용(창작)이 없는지, 각 섹션의 `source`가 누락되지 않았는지
5. **내용 검수** (plan.md ↔ interview-log 대조):
   - 수치가 interview-log의 확정 팩트와 일치하는지
   - `(미확정)` 표기가 남아 있는데 산출물에는 확정처럼 보이는 문구가 없는지
   - 오탈자, 띄어쓰기, 존칭/문체 통일
6. **산출물 세대 대응성**: 최신 pptx·md·html·docx가 모두 같은 plan.md 세대인지 판정한다 — 채번이 확장자별 독립이므로 버전 번호 매칭이 아니라 접두어 + 내용 대조로 판정한다. 오래된 세대의 산출물이 있으면 재생성 대상으로 보고한다.
7. **발견사항 보고**: 심각도 순으로 정리 — 🔴 (사실 오류·수치 불일치) / 🟡 (표현·구조 개선) / ⚪ (선택 사항).
8. **수정 적용**: 사용자가 수정을 승인하면 **plan.md를 수정** → 파생물(slides.json·report.json) 재생성 → `build_ppt.py`·`build_doc.py` 재실행 (확장자별 버전 각각 +1). 파생물이나 output만 고치지 않는다.
9. **인터뷰 로그 갱신**: 검수 중 새로 확정된 사실은 `<P>/docs/interview-log.md`에 추가.

## 주의

- 🔴 사항은 반드시 재생성 전에 해결. 사용자 승인 없이 내용을 바꾸지 않는다.
- 디자인 문제는 층위별로 분류해 별도 보고한다: PPT(색/폰트/배치) → `ppt-design` 스킬·build_ppt.py, 문서(html/docx 스타일) → build_doc.py. 콘텐츠 문제와 섞지 않는다.
