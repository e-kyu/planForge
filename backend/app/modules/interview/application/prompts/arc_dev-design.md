## 이번 인터뷰 아크: 개발설계서 아크 (서사 주제 그룹 · 체크리스트 · plan 구성 가이드)

### 아크 서사와 주제 그룹 (예시 질문 포함)

- **개발설계서 아크**: 배경·요구사항 → 설계 결정 설문 (아래 주제 그룹 5개) →
  일정·리스크. 각 주제는 결정 + 이유(근거) + 대안 검토 여부를 함께 수집해 주제당
  1개 팩트로 적립한다. 답이 정해지지 않은 항목은 `(미확정)` 팩트로 적립하고
  "언제까지·어떻게 확정할지"까지 묻는다. 라운드당 최대 4문항이므로 주제 그룹 5개는
  최소 2라운드에 나눠 묻는다. 예시 질문(옵션 카드 = 라벨 — 설명):
  - 아키텍처 스타일·시스템 구성 → "시스템 전체 구조는 어느 방향으로 잡고
    싶으신가요?"
    (레이어드 모놀리식 — 계층 분리·단일 배포, 운영이 단순) / (모듈러 모놀리식 —
    모듈 경계를 명시해 추후 분리 가능) / (마이크로서비스 — 도메인별 독립 배포,
    팀·트래픽이 클 때). 계층 구성 요소와 통신 방식(동기 API/메시지 큐)도 함께
    확인한다.
  - 기술 스택·모듈/패키지 구조 → "언어·프레임워크·버전과 패키지 구조는 어떻게
    정하고 싶으신가요?"
    (FastAPI + SQLAlchemy 2.x — 비동기 지원·팀 경험; 대안 Django는 전환 비용으로
    제외) / (Spring Boot 3.x — 엔터프라이즈 표준·인력 확보). 디렉터리 레이아웃과
    모듈별 책임 경계는 서술형(allow_free)으로 수집한다.
  - 데이터 모델·API/인터페이스 규약 → "핵심 엔티티·관계와 API 규약은 어떻게
    정하고 싶으신가요?"
    (REST + JSON, 오류 응답 통일 — 표준·도구 친화적) / (계약 우선 OpenAPI —
    스키마 고정·코드 생성). 핵심 엔티티와 관계는 서술형으로 수집한다.
  - 디자인 패턴·제약·비목표 → "어디에 어떤 패턴을 쓰고 싶으신지, 하지 않을
    것은 무엇인지 알려 주시겠어요?" 서술형으로 "패턴 + 적용 위치 + 이유"와 하지
    않는 것(비목표·금지 항목)을 명시로 수집한다 — AI 코딩 도구가 임의 확장·
    과설계하지 않도록 범위를 고정하는 목적이다.
  - 테스트·배포 전략 → "테스트 범위와 배포 방식은 어떻게 가져가고 싶으신가요?"
    (단위+통합 위주 — CI에서 전체 실행) / (E2E 포함 — 핵심 시나리오 검증).
    배포 환경·방식·롤백 기준도 함께 확인한다.

  문서 태그 `[문서: 개발설계서]`를 붙인다 (단일 문서 프로젝트는 태그 없음 — 아래
  plan.md 포맷 섹션의 태그 규칙 따름).
  - 결정표: `[유형: 표][문서: 개발설계서]` — 헤더 예시 `- 표: [항목 | 선택 | 이유 | 상태]`,
    행은 확정 팩트에서만 채우고 결정되지 않은 항목은 상태 칸에 `(미확정)`을 적는다.
    (기술 스택·모듈 구조·API 규약·제약·비목표를 각각 1개 표로 정리)
  - 아키텍처: `[유형: 구성][문서: 개발설계서]` — `- 구성:` 아래 `계층명 | 박스 라벨, ...`
    한 줄 = 계층 1개 (계층 최대 6개·계층당 박스 최대 6개, 라벨 안에 쉼표 금지 — 서버가 검증한다).
